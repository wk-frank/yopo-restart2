# 阶段 C 三进程墙钟闭环复验

在安装项目依赖的 Linux 或 WSL 项目目录执行。每个输出目录须尚未创建。

```sh
python -m yopo_l0.stage_c_sim run --scenario normal --out out/stage-c-normal
python -m yopo_l0.stage_c_sim run --scenario faults --out out/stage-c-faults
python -m yopo_l0.stage_c_evidence out/stage-c-normal --out out/stage-c-recomputed.json
python -m pytest -q tests/test_stage_c_sim.py tests/test_stage_c_evidence.py
```

可用 `--duration-s` 延长正常场景从三机 CTBR 启动后的采样时间。正常用例是 5 m 平面深度场景，采用 0.45 m/s 的软件回放候选。它用于检查端到端接线和实际运动证据，报告始终使用固定的 900 m 门槛。

三个板端实例使用同一个 `board_runtime` 入口。每个实例绑定独立的里程计、深度源、推理服务、邻机 UDP 接口和飞控接收端。感知层在同一曝光生成网络输入及三态深度，使用曝光前后的里程计插值。开机覆盖来自明确标记、带时标的合成进近回放；后续观测来自主机运行中的平面深度源。推理通过本机 IPC 回放可复现的 FP32 候选批次，逐实例保留请求、回复、期限与模型标识。

每个候选在提交前经停车约束、观测几何和两机包络核验。现行轨迹的剩余制动范围继续接受邻机复核。故障时保留同一条获准轨迹，最多执行 130 ms 剩余前缀后进入连续制动尾，少于该软件用例的 150 ms 响应余量。接收端保留实际制动分支起点和权限变更。新净视距无法支持剩余停距时撤销自动输出，主机软件动力学随后按其本地失效模型收敛。

`faults` 分别运行四个隔离场景。也可直接指定对应的 `--scenario`。

- `all-blind` 注入全零深度，复核最新帧失效、取消前进计划、接收端制动以及后续新帧。
- `inference-timeout` 暂停一机的独立推理服务，复核规划请求过期、控制继续运行及经验证制动。
- `one-way-drop` 让一个模拟改轨数据包只发给第三架，保留判定机先前收到的新鲜包；从接受记录和物理可达域核对拒绝。
- `restart` 暂停并重启一个板端进程，复核接收端旧指令到期、其他实例继续运行、新会话隔离及核验后的重新加入。

每次运行保存 `manifest.json`、`faults.jsonl`、裁判 `judge.jsonl`，以及逐板配置、输入、深度阵列、推理日志和收发控制记录。独立裁判只读主机动力学真值。动力学用实际接收的 PVA 或 CTBR 指令，其中 CTBR 使用 FRD 机体角速率与集体推力。裁判位置没有传给板端；板端只接收量化的模拟里程计及对应相机观测。

复算必须在同一实际 CTBR 权限段、同一时刻对齐里程计与独立裁判的水平位置，双方同时从该段起点达到 900 m 才通过。权限变更、过期空窗、数据缺失和超过 0.25 s 的相邻样本都会断段。历史六机锁步记录单独列出。正常短场景输出真实距离，预期为 900 m 未达标。逐板物理台架结论保留未验证。
