# 阶段 C D435 曝光与首段通行

每个实例以 D435 序列号绑定一个 `BoardPerception`。`push_odometry` 接收本机单调时钟下的位姿，`observe` 接收校正到 160×96 的原始深度及曝光硬件时标。实例要求曝光时刻及映射误差区间被两个有效的实测位姿样本包围，并使用该曝光位姿及相机外参投影。扫掠覆盖和障碍净空计算包含时钟误差区间内的平移及旋转界，界值随曝光记录。`tracking_state` 返回当前有效里程计。

`DepthExposure` 使用同一份曝光生成网络输入和三态几何。零值、超量程回波、窄视场之外及未证实的无回波像素属于未知。只有同时带 `+inf` 和明确来源的远距自由空间掩码才能证明自由空间。`check_first_segment` 使用当前机体中心为扫掠起点，逐段验证整个球体足迹，包括分段间隔和几何余量。机体当下占据的邻域可作为保持证据。向前扩展到近盲带前，须有时间限内的实测深度覆盖。若机械运动和相机外参使历史帧无法提供覆盖，首段保持拒绝。

全盲帧撤销当前帧的规划资格。时间回退、定位或坐标跳变和缺少曝光位姿插值样本均提升感知代次并作废关联缓存。入口应以该代次撤销关联计划和未采用的推理结果。相机时钟回退后须重新调用 `synchronize_camera_clock` 安装校准映射。

启用 `archive_dir` 后可将每份已消费深度及远距空间来源掩码写入 NPZ。配套 JSONL 中 `depth_observed` 保留序列号、原曝光时标、映射误差、内外参、位姿样本和对应文件。使用 `DepthExposure.from_archive` 读回帧，把日志中的两个位姿样本送入新实例，即可重新计算曝光位姿及网络、几何掩码。`depth_geometry_decision` 保留校验路径、机体半径、细分保守半径和每段覆盖所依据的曝光。

```sh
.venv/bin/python -m pytest -q tests/test_board_perception.py tests/test_d435_live.py tests/test_depth_only.py
```

本地回放用例覆盖非零相机偏置、运动中的曝光插值、近盲带缺证和补证、有效帧切到全盲，以及时钟和定位故障。D435 实拍数据与设备时钟映射误差上界在三板台架核验。
