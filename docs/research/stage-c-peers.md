# 阶段 C 邻机占用检查

板端通过独立 UDP 端口发送带会话、坐标版本和序号的多项式计划。每份报文同时带该机里程计实测位置及其公共时标，最多 349 字节。接收端用配置的端点和成员身份匹配来源，按 CRC 检查传输完整性。部署时所有实例使用共同的坐标版本、对时时差上界和覆盖全队及降级运动的物理速度上界。

板端启动后用 `PeerGuard.broadcast` 发布本机实测保持状态，用 `poll` 接收报文。周期由 `next_broadcast_s` 提供，三机在 15 Hz 下的相位间隔为约 22.2 ms。各成员都有新鲜保持证据后才能进入共享空间。准备提交时用 `check` 检查从当前时刻连续覆盖切换、执行和完整制动尾的轨迹，尾端必须静止。持续执行中复查同一轨迹的剩余有效段。控制循环可用 `availability` 检查缺报、坐标不符、过期与重启隔离。运行入口收到拒绝时须停止发布新计划并沿此前已验证的降级轨迹执行。

检查同时考虑传输窗口内的双轨及邻机最后一个实测位置的物理可达域。后者按实测位置龄期、相对时差上界和物理速度上界扩张至本机制动结束。两个机体的半径、定位、跟踪及轨迹表示误差计入分离量。位置连续性、速度上界及分离检查在轨迹各段覆盖整个时间区间；触边或无法证明分离均拒绝提交。

已知成员换会话后进入隔离。核验者使用 `pending_session` 确认所见会话，再用 `verify_rejoin` 核验指定会话的新鲜实测位置、正确坐标版本和与位置一致的保持计划。复查轨迹分离后恢复共享空间提交。旧会话报文、重复报文和乱序报文均不刷新有效性。

`peer_tx`、`peer_tx_dropped`、`peer_rx` 和 `peer_rx_rejected` 保留报文和收发时标。`peer_decision` 记录候选轨迹、制动区间、参与检查的邻机计划序号、实测位置、扩张到制动结束的半径及误差预算。测试将一份冲突改轨只发给另一架邻机，被漏发的接收端仍保有上一份新鲜报文，完整制动尾因可达域相交被拒绝。
